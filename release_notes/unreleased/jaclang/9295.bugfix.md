- **Fix: Builtin keyword arguments resolve by name on the ES target**: `sorted(xs, reverse=True)` no longer crashes with `key is not a function` on the client (ES) target. Builtin calls used to forward keyword-argument values into the compiled JavaScript in source order rather than by name, so a keyword argument could land in the wrong parameter slot -- `sorted(xs, key=f, reverse=True)` and `sorted(xs, reverse=True, key=f)` could compile to different, sometimes incorrect, behavior, and `pow(exp=3, base=n)` or `complex(imag=2, real=1)` could silently swap their arguments. Keyword arguments to builtins and builtin class constructors are now slotted using the signature the type checker resolved from the stubs, so any builtin with a fixed signature is covered without a hand-maintained list. Giving one of these builtins the same argument both positionally and by keyword is now reported as a compile error instead of silently mis-compiling.
