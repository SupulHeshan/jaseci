- **Fix: a `for` target or `with ... as` alias that rebinds a variable is type-checked** (#10375): Python and native store every binding of a name in a function in one variable, but the checker treated a loop's or `with` block's binding as a separate variable and never compared it with the function's other bindings of that name. Rebinding a local, parameter or annotated variable to an incompatible type through a `for` target or `with` alias is now `E1001`, the same as a plain reassignment, so `title = Label(); for (k, title) in pairs {}` is reported instead of passing `jac check` and crashing native code. Tuple/list unpacking and walrus rebinds are now checked the same way. Loops that only reuse a name with different types are reported when a later read would see the wrong type, and so is a read between a loop and a later assignment of a different type.
