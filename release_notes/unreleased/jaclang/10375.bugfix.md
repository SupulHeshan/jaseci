- **Fix: a `for` target or `with ... as` alias that rebinds a variable is type-checked** (#10375): these binders now bind the function's local, as an assignment does, instead of a loop- or block-only variable that shadowed it. Rebinding a name to an incompatible type is now `E1001`, the same as a plain reassignment, so `title = Label(); for (k, title) in pairs {}` is reported instead of passing `jac check` and crashing native code. The same check now covers tuple/list unpacking and walrus rebinds. After a loop, the checker types the name as the variable it is at runtime; inside the loop, a compatible rebind takes the element's type. Reusing one name with different types across loops in a function is now an error. A ref loop (`for x in &xs`, `for m in &mut xs`, `flow for`) still binds a fresh loan for the loop, and naming it like another variable of the function is now `E1306`, since that variable would hold the loan after the loop. A comprehension's variable no longer resolves outside the comprehension.
